# v0.2.0 设计方案（六项体验改进）

- 日期：2026-11-19
- 状态：待评审（评审通过后才进入实施计划）
- 目标仓库：本仓库 `zz-deploy-desktop`，版本已改为 `0.2.0`
- 关联文档：`docs/superpowers/specs/2026-10-13-zz-deploy-desktop-design.md`（v0.1 总体设计）

---

## 背景与目标

0.1.x 上线后收到六条使用反馈，都在「少点几下、少踩坑」这一条主线上：

1. 单次部署与收藏快速部署也需要「构建成功即自动上线」（批量部署已有）。
2. 任务列表只有类型切换 + 一个关键词框，缺环境筛选。
3. 自研日志渲染（逐行 span + 自研高亮 + 自研查找）该换成 Monaco，换来虚拟滚动、真编辑器体验。
4. 标签栏缺右键菜单，关多个标签只能一个个点。
5. 新建部署 / 批量部署的项目网格看不出还能往下滚。
6. 收藏需要备注和彩色标签，方便快速找到；单条收藏与批量收藏都要。

## 非目标

- 不改 ITSM 服务端，不新增业务接口（沿用 HTML 解析 + 既有 JSON 接口）。
- 不做日志全文检索服务端能力、不做跨任务搜索。
- 不给收藏做文件夹/分组（标签足够）。
- 不改登录、更新、托盘、通知既有行为（除第 1 条自动上线的通知文案）。
- 不把 `logHighlight.ts` 的规则原样保留成两套实现——只保留一份（迁到 Monaco 语法）。

---

## 决策摘要（已与使用者确认）

| # | 决策 | 结论 |
|---|---|---|
| 1 | 日志渲染 | 使用 Monaco（非 CodeMirror），自写 `zzlog` 语法；实时日志与历史日志预览共用一个组件 |
| 2 | 自动上线 | 复用 `stores/batch.ts` 的认领+轮询机制，单次部署开一个「1 项批次」；默认关、不记忆、不写进收藏 |
| 3 | 收藏备注/标签 | 单条收藏与批量收藏都要；用户自己挑颜色 |
| 4 | 标签颜色存储 | **全局标签表**（名字 → 颜色），收藏里只存标签名 |
| 5 | 任务筛选 | 走服务端：`env` + `search` 两个参数（与平台网页一致）；环境列表从任务列表页的 `env` select 解析 |
| 6 | 标签栏菜单 | reka-ui 的 ContextMenu（已是依赖），补 shadcn 风格包装 |
| 7 | 项目网格 | 保留网格，加计数、底部渐隐、"继续向下滚动"提示 |

## 一、自动上线（对应需求 1）

### 现状

- `stores/batch.ts` 已实现：提交前记录各部署类型的最大 `taskId`（baseline），提交后轮询任务列表，按 **比 baseline 新 + commit hash 对得上 + 分支对得上** 认领新任务，观察到构建成功才调 `/up/` 上线，最后汇总一条通知。
- 提交接口只回 302、**不返回 taskId**，所以单次部署也必须走同一套认领。

### 设计

**复用 batch store，但只在勾选自动上线时才开一个「1 项批次」。**

不勾选时**完全走现有路径**（不开批次、不认领、单条可点击通知），这样：

- 既有通知行为不变（点通知打开该任务日志的 `id` 还在）。
- 批量页的「最近批次」面板不会被一堆单次部署刷屏。

勾选时的批次改动：

- `BatchRun` 增 `kind: "batch" | "single"`（由 `start()` 入参决定）：`single` 的 run 不进批量页「最近批次」列表（`runs` 仍保留，供结算与抑制单条通知）。
- `notifyRun()` 按 `kind` 切换文案：
  - `single`：`部署完成（含自动上线）`，正文「项目 · 环境 · 成功/失败（· 已上线/上线失败；未识别到任务时说明不会自动上线）」。
  - `batch`：保持现有「批量部署：…」文案。
- `sendSystemNotification` 支持可选 `id`：`single` 且认领到 taskId 时传 taskId，保住「点通知 → 打开该任务日志」。
- `matches()` 增补 **项目名比对**：两边都非空时，用 `cleanProjectName()`（去掉 `（tke_node）` 这类后缀）+ 小写比对；不一致则不认领。这条同时降低批量部署里"认到同 commit 的别的项目"的概率。
- 认领失败兜底不变：30 分钟 TTL 后汇总，没认领到的项不会上线——UI 文案要写明"若未能识别到任务，将不会自动上线"。

### UI

| 位置 | 元素 |
|---|---|
| `DeployWizard.vue` 的确认区（"即将部署：…"下面） | checkbox「构建成功后自动上线」+ 勾选后红字警告（沿用批量页的警告样式与措辞） |
| `FavoritesView.vue` 展开面板的「提交部署」按钮上方 | 同上 checkbox，**每次展开独立、默认关** |

- 两个开关都不持久化、不写进收藏（与批量收藏"不记自动上线开关"的既有原则一致）。
- 提交成功后向导仍按现行为关闭自己并跳任务列表；是否上线由系统通知告知。

### 测试

- `stores/batch.test.ts`：`single` 批次文案与通知 `id`；`single` 不出现在批量页「最近批次」（`kind === "batch"` 过滤）；`matches()` 项目名不匹配时不认领；单次 autoOnline 成功后调用 `submitOnline`。
- `DeployWizard.test.ts` / `FavoritesView.test.ts`：勾选后提交时 `batches.start` 收到 `{ kind: "single", autoOnline: true }` 与完整 item（env/project/branch/version）；**不勾选时不调用 `start`**。

## 二、任务列表筛选（对应需求 2）

### 现状与依据

- 服务端任务列表页导航栏自带 `<select name="env">`，与 `search` 一起 GET 提交；使用者已确认 `?env=1&search=test-admin` 可叠加生效。
- 客户端当前只传 `search`，`env` 完全没用；分页链接由服务端给出且不带 `env`，但**分页 URL 由我们自己拼**，可以补上。
- 该 select 的环境列表（23 个，含「马甲账号新加坡机房 / 香港adx / us-gke …」）比 `api/deploy.ts` 里硬编码的 `ENVS`（9 个）更全，且名字是服务端权威。

### 设计

- `api/deploy.ts`：`fetchTaskList(type, page, opts: { search: string; envId: number })`，URL 带 `page`、`search`、`env`（`envId === 0` 时省略即"全部环境"）。
- `api/parser.ts`：
  - `TaskListResult` 增 `envs: { id: number; name: string }[]`，从 `select[name="env"]` 解析（跳过 `value="0"` 的"按环境筛选"占位项）。
  - 解析失败时返回空数组，不影响任务解析。
- `stores/tasks.ts`：
  - 新状态 `envId = ref(0)`、`envsByType = ref<Record<DeployType, {id,name}[]>>({auto: [], docker: []})`；`envs` 为当前类型的计算属性。
  - **两种部署类型的 env 目录不同**（实测：自动化的 select 有 23 个环境，Docker 只有 14 个；fixture 里 `tasks_auto.html` / `tasks_docker.html` 已能复现）。因此：切换部署类型时 `envId` **重置为 0**，并按类型分别缓存目录——避免把只存在于另一条路由的 env id 打过去。
  - `setEnv(id)` → `page=1` + `refresh()`；`refresh()` 传 `{ search, envId }`；成功响应里该类型的 `envs` 非空才覆盖（避免某次解析失败把下拉清空）。
  - 筛选条件**不持久化**（每次启动回到"全部环境"）。
- `TaskListView.vue`：
  - 类型切换按钮右侧加环境下拉（`components/ui/select`，第一项「全部环境」`value=0`）。
  - 关键词框沿用，占位文案「搜索标题 / 项目 / 提交人（回车）」，回车 `applySearch`；右侧保留刷新按钮与"最后刷新"。
  - 有筛选条件时显示一行小结：「筛选：正式环境 · 关键词 "xxx" · 共 N 页」，带「清除筛选」。
  - 空结果区分两种文案：无筛选时"暂无数据"；有筛选时"没有符合条件的任务"。

### 测试

- parser：从 `tasks_auto.html` 解析出 23 个环境、从 `tasks_docker.html` 解析出 14 个、均无 `value=0` 项。
- api：URL 含 `env=`（用 http mock 断言 query）。
- store：`setEnv` 会重置 page 并带上 envId；`envs` 不会被空响应清空；**切换部署类型把 envId 归零**且两类型目录互不覆盖。
- view：下拉切换触发 `setEnv`；切换类型后下拉回到「全部环境」；「清除筛选」同时清 envId 与 search。

## 三、Monaco 日志渲染（对应需求 3）

### 现状

- `LogView.vue`：`v-for` 逐行 span + `logHighlight.ts`（行级语气 + hash 词法）+ 自研搜索（命中片段重着色、`data-line` 跳转）+ `pending` 行 + 自动滚动。
- `HistoryView.vue` 展开预览同样用 `highlightLineCached`。
- 缓冲区上限 5000 行（`lib/ansi.ts`），大 chunk 分片解析（`lib/logLoad.ts`）。

### 设计

**新组件 `src/components/log/LogEditor.vue`**

- 依赖：`monaco-editor`（仅引入 `monaco-editor/esm/vs/editor/editor.api`，不引 basic-languages / 语言服务）。
- Worker：`MonacoEnvironment.getWorker` → `new Worker(new URL('monaco-editor/esm/vs/editor/editor.worker?worker', import.meta.url), { type: 'module' })`（Vite 打包为本地资源，Tauri 离线可用）。
- 编辑器配置：只读、无 minimap、无行号、`wordWrap: 'on'`、`scrollBeyondLastLine: false`、`fontSize: 12`、等宽字体、`automaticLayout: true`、`ariaLabel: '构建日志'`、自定义主题 `zzlog-dark`（背景 `#0b0d12`，token 色沿用现有调色板）。
- Props：`lines: LogLine[]`（**不是 `string[]`**：进度行靠稳定 `id` 原地改写、靠 `updates > 1` 压暗）、`pending: string`、`autoScroll: boolean`、`heightClass?: string`。Expose：`scrollToBottom()`、`getText()`。
- 数据同步（关键，避免每帧全量 `setValue`）。现状约束：
  - docker 进度行是**原地改写已落地的行**（`lib/ansi.ts` 的 `buf.lines[idx].text = line`，`updates += 1`）；
  - 缓冲超 5000 行时**从头部丢行**（`dropped` 递增）；
  - 服务端换窗口会 `reset()`（清空 lines 且 `dropped` 归零）；
  - 「清空」按钮 `splice` 掉所有行且 `dropped` 不变。

  因此按「id 游标」同步，而不是按长度或前缀：

  - 组件记录上次同步状态：`lastId`（模型最后一行对应的 `LogLine.id`）、`syncedDropped`、`syncedPending`、以及 `id → 已同步文本` 的环形记录（只留最近 1000 条，足够覆盖进度行回写）。
  - **头部丢行**：`next.dropped > syncedDropped` → 删掉模型开头 `(next.dropped - syncedDropped)` 行（`applyEdits` 一次 delete）。
  - **原地改写**：在 `id <= lastId` 的尾部窗口（最近 500 行）里，文本与记录不一致的行 → 对这些行逐一发 replace edit（整行范围）。若不一致行数 > 50 或 id 对不上 → 回退整篇 `setValue`。
  - **追加**：`id > lastId` 的行 → 在模型末尾一次 `applyEdits` 追加（tokenize 只跑新行）。
  - **清空 / reset 识别**：`next.lines` 为空，或 `next.dropped < syncedDropped`（reset 把 dropped 归零），或模型里找不到 `lastId` → 整篇重置（清空即 `setValue("")`）。
  - **pending 行**：始终是模型的最后一行。内容变化时 replace 该行；为空时删掉该行。pending 存在时追加/丢行的 edit 位置要避开它（模型行数 = 已落地行 + pending 行）。
  - 上述判定抽成纯函数 `planModelSync(prev, next): { mode: "edits", edits } | { mode: "reset", text }`（`src/lib/logModel.ts`），不依赖 monaco，单测直接断言 edit 列表。
- 进度行压暗：对 `updates > 1` 的行加整行 decoration（`className: "log-progress-dim"`，对应现在的 `opacity-80`）。用 `createDecorationsCollection` 维护，数量很小；头部丢行时 decoration 随内容一起移动，不需要重算。
- 大块历史日志（`HistoryView`）一次性给全量行：首次同步走 `reset` 路径（一次性 `setValue`），后续不再变化。
- 高亮：`src/lib/logLanguage.ts` 定义 Monarch 语法 `zzlog`：
  - 行级规则（顺序即优先级，沿用现有语义"先失败、再警告、成功、结构行、进度"）：`^.*(error|failed|fatal|exception|npm err!|cannot find|失败|错误|异常).*$` → `danger`；warn → `warning`；success → `success`；`^(step \d+/\d+|\[pipeline\]|\+\s|>\s|#\s)` → `step`；docker 进度行 → `dim`。
  - 词法规则：`sha256:[0-9a-f]{8,}`、`\b[0-9a-f]{7,40}\b` → `hash`。
  - 同时导出纯函数 `lineTone(line)`（返回 token 名或空），语法与测试共用一份判定逻辑。
  - 主题把 token 映射到现有颜色（红/琥珀/绿/天蓝/压暗/琥珀 hash），视觉与现在一致。
- 查找：**删掉自研搜索条**，改用 Monaco 自带 find widget（`Ctrl/Cmd+F` 原生可用，带命中计数与上/下一个）。头部只保留：项目/环境、连接状态、服务端原话、自动滚动 checkbox、清空、复制。
- 自动滚动：同步后若 `autoScroll` → `editor.revealLine(model.getLineCount(), ScrollType.Immediate)`；标签从隐藏变可见（`v-show` 后 `layout` 为 0）时先 `editor.layout()` 再滚到底（对应现有 `isActive` watcher 的坑）。
- `pending` 的闪烁光标用 decoration（`after.contentText: '▌'` + CSS 动画），不写进模型文本，避免被复制走。

**历史日志预览**：`HistoryView.vue` 展开区改用同一个 `LogEditor`（`autoScroll: false`、固定高度、只读），删掉逐行 span 与 `highlightLineCached`。大日志"仅显示最后 5000 行"的提示保持。

**删除**：`src/lib/logHighlight.ts` 与其测试（规则迁到 `logLanguage.ts`）；`SEARCH_HIT_CLS` / `SEARCH_CURRENT_CLS` / `markMatches` 不再存在。

### 构建与测试影响

- `vite.config.ts`：`chunkSizeWarningLimit` 提到 2000（Monaco 约 +1MB，桌面端本地加载，可接受）；monaco 作为独立 chunk 便于缓存。
- 单测：
  - `logModel.test.ts`：纯追加、头部丢行（delete + 追加）、进度行原地改写（单行 replace）、改写过多回退整体重置、清空、`dropped` 归零的 reset、pending 行替换/删除、pending 存在时追加位置正确。
  - `logLanguage.test.ts`：把现有 `logHighlight.test.ts` 的用例迁过来（行级语气优先级、hash 词法）。
  - `LogEditor.test.ts` / `LogView.test.ts`：`vi.mock('monaco-editor/...')` 用假 editor 记录 `model.applyEdits` / `revealLine` 调用；现有"自动滚动/隐藏时不动/切回补滚/服务端快照 reset/服务端原话"用例保留，改为断言这些调用。
  - jsdom 下不加载真实 monaco（体积与 worker 都不适合）。

### 风险

- Monaco 在 `v-show` 隐藏标签里布局为 0：必须显式 `layout()`（已在设计中处理）。
- 5000 行整篇 `setValue` 重置（丢行时）会有一次几百毫秒的 tokenize：只在缓冲区超限后发生，可接受；必要时按可见范围渲染的优化留到后续。
- 测试桩与真实 Monaco 行为差异：用假 editor 保证同步逻辑正确，交互体验靠手工验证（`npm run dev` + 真实任务日志）。

## 四、标签栏右键菜单（对应需求 4）

### 设计

- 新增 `components/ui/context-menu/*`（shadcn-vue 风格包装 reka-ui `ContextMenu`：Root / Trigger / Content / Item / Separator）。
- `TabBar.vue`：每个标签用 `ContextMenu` 包裹，`ContextMenuTrigger as="div"`（保持现有 click 聚焦行为）。右键不切换激活标签，菜单动作作用于**右键的那个标签**。
- 菜单项与禁用条件：

| 项 | 行为 | 禁用条件 |
|---|---|---|
| 关闭 | 关掉该标签 | 无 |
| 关闭其它标签 | 关掉除它以外的全部 | 只有一个标签 |
| 关闭右侧标签 | 关掉数组顺序中它右边的所有标签 | 它已是最右 |
| 关闭全部标签 | 关掉所有 | 无标签时菜单不出现 |

- `stores/tabs.ts` 新增 `closeMany(ids: string[])`：从右往左逐个 `close()`，保证关闭激活标签时的"优先右邻"语义逐次正确；`closeByKind` 改为调用它（行为不变）。
- 日志流二次确认：把待关闭的标签集合整体判断——其中**有任意一个**日志处于 connecting/connected，则弹一次确认（文案「其中 N 个日志仍在输出中，确认关闭？」），确认后一次性关掉；没有则直接关。
- 分隔线：`关闭其它/右侧/全部` 与 `关闭` 之间加一条 Separator。

### 测试

- `tabs.test.ts`：`closeMany` 关激活标签后的聚焦结果、关闭顺序、未知 id 忽略。
- `TabBar.test.ts`（新建）：右键菜单项与禁用条件；流式日志时弹确认、取消不关、确认全关。

## 五、项目网格可滚动提示（对应需求 5）

### 现状

- `DeployWizard.vue`：`flex flex-wrap gap-2 max-h-[240px] overflow-auto`，标题有「项目（X / N）」。
- `BatchDeployView.vue`：`max-h-[200px]`，**没有**计数。
- macOS 覆盖式滚动条在不滚动时不显示，因此看不出还有内容。

### 设计

- 抽公共组件 `components/deploy/ProjectGrid.vue`（两处共用，消除重复）：
  - Props：`projects`、`selectedId`、`maxHeightClass`；事件 `pick`。
  - 容器相对定位 + `overflow-auto`；底部覆盖一层 `pointer-events-none` 的渐隐（`bg-gradient` 从透明到 `bg-bg`）。
  - `hasMore`（`scrollHeight - scrollTop - clientHeight > 4`）时，底部居中显示小胶囊：「共 N 个项目 · 继续向下滚动」；滚到底后消失。
  - 选中项自动 `scrollIntoView({ block: 'nearest' })`（筛选后选中项可能不在视口内）。
  - `ResizeObserver` + `scroll` 监听重算 `hasMore`；组件卸载时断开。
- 两处标题统一：「项目（已筛选 X / 共 N）」；批量页首次有计数。
- 保留现有 `max-h` 与 `flex-wrap`（"一眼扫全部"的习惯不变）。

### 测试

- `ProjectGrid.test.ts`（jsdom 无布局，按 `LogView.test.ts` 的写法伪造 `scrollHeight`/`clientHeight`/`scrollTop`）：内容溢出时显示提示、滚到底后隐藏、不溢出时不显示；点击发出 `pick`。

## 六、收藏备注与彩色标签（对应需求 6）

### 数据模型

**Rust（`src-tauri/src/commands/favorites.rs`、`batch_favorites.rs`）**

- `Favorite` / `BatchFavorite` 各加两个字段（`#[serde(default)]`，老数据自动为空，无需迁移命令）：
  ```rust
  #[serde(default)] pub note: String,
  #[serde(default)] pub tags: Vec<String>,
  ```
- 新增全局标签表，存 `favorites.json` 的 `tags` 键：
  ```rust
  pub struct TagDef { pub name: String, pub color: String } // color: "#RRGGBB"
  ```
- 新增命令（注册进 `lib.rs`）：

| 命令 | 语义 |
|---|---|
| `tags_list` | 读全部标签 |
| `tags_upsert` | `{ oldName?: string, name, color }`：新增 / 改色 / 改名（按 name 去重；带 `oldName` 即改名，级联把两处收藏里的旧名替换成新名） |
| `tags_delete` | 删除标签，并级联从所有单条/批量收藏里移除该标签 |

- 新命令（元数据单独写，避免与"向导保存收藏"互相覆盖）：

| 命令 | 语义 |
|---|---|
| `favorites_meta_set` | `{ id, note, tags }` → 只改备注与标签 |
| `batch_favorites_meta_set` | 同上 |

- **保留既有元数据的规则**：`favorites_save`（来自向导）不改动已有记录的 `note`/`tags`；`batch_favorites_save`（来自批量页"保存修改"）同理保留。理由：向导与批量页都只负责"部署参数"，备注标签是收藏页的编辑职责，两边同时整对象覆盖必然打架（既有的去重覆盖正是这个坑：同项目再收藏一次会把备注标签冲掉）。
- 颜色校验：只接受 `#RRGGBB`；非法值回退到按名字哈希取的默认色。名字去空白、长度上限 24 字符；每条收藏标签数上限 20。

**TS**

- `api/tags.ts`（list/upsert/delete）+ `stores/tags.ts`（`items`、`byName`、`colorOf(name)`、`upsert`、`remove`）。
- `api/favorites.ts` / `api/batchFavorites.ts`：`Favorite`、`BatchFavorite` 增加 `note?: string`、`tags?: string[]`；新增 `favoritesMetaSet` / `batchFavoritesMetaSet`。
- 默认色板（10 色，深色主题下可读）：slate / red / orange / amber / emerald / teal / sky / indigo / violet / pink，取 Tailwind 对应 token；`colorOf()` 对未登记的标签按名字哈希取一个，保证同一名字到处同色。

### UI

**收藏页（`FavoritesView.vue`）**

- 行内：项目名后跟彩色标签胶囊；第二行显示备注（截断 + `title` 悬浮全文）。
- 「编辑」按钮（与「快速部署」「删除」同排）→ 弹窗：备注 textarea + 标签编辑器（已选胶囊可移除；下方候选标签可点选；「新建标签」输入名字并从 10 色板挑色）。保存调 `favorites_meta_set`。
- 筛选：顶部在关键词框旁加**标签筛选行**（点选多个标签时按 **AND** 收窄，再与关键词取交集）；关键词也匹配备注与标签名。
- 已选标签的筛选状态不持久化。

**批量部署页（`BatchDeployView.vue`）**

- 批量收藏胶囊：显示彩色标签与备注（备注做 `title`）；每份收藏右侧加「编辑备注/标签」入口，复用同一个弹窗组件（`components/favorites/MetaDialog.vue`，props 区分单条/批量）。
- 批量页的收藏胶囊很多时按标签筛选：与收藏页同一行 chips 组件（`TagFilterBar.vue`）。

**标签管理（改名 / 改色 / 删除）**

- 入口：`MetaDialog` 里的「管理标签」按钮 → `TagManagerDialog`（列出全部标签：色板改色、改名输入、删除；删除二次确认并说明会从所有收藏里移除）。
- 新增标签也可在 `MetaDialog` 里直接输入名字并挑色（等价于 `tags_upsert` 新增）。
- 改色/改名/删除都走 §6 的 `tags_upsert` / `tags_delete`（改名带旧名、级联更新单条与批量收藏）。

### 兼容

- 老 `favorites.json` / `batch_favorites.json` 缺字段 → `serde(default)` 读成空，写回时补全。
- 标签表键不存在 → 空表。
- 未知标签（收藏里有名字但注册表没有，例如手工改过文件）→ 显示为默认灰色，编辑时自动登记。

### 测试

- Rust：`favorites_meta_set` 不覆盖部署字段；`favorites_save` 保留既有 note/tags；`tags_upsert` 新增/改色/改名级联（旧名从单条与批量收藏里替换）；`tags_delete` 级联清理两处；颜色非法回退；名字长度/标签数量上限校验。
- TS：`tags` store 的 `colorOf` 稳定性（同名同色）与未登记标签的灰色兜底；收藏页筛选（标签 AND + 关键词命中备注/标签）；meta 弹窗保存调用正确命令；标签管理弹窗的改名/删除调用与本地状态更新；批量页同样。

## 交付顺序

| 阶段 | 内容 | 理由 |
|---|---|---|
| P1 | 标签栏右键菜单 | 纯前端、无数据变更、独立 |
| P2 | 项目网格可滚动提示 | 纯 UI，抽公共组件后两页同享 |
| P3 | 任务列表环境筛选 | 解析 + store + 视图，闭环小 |
| P4 | 自动上线（单次 + 收藏） | 复用 batch store，需谨慎的认领逻辑 |
| P5 | 收藏备注与彩色标签 | 涉及 Rust 存储与两条 IPC，改动面中等 |
| P6 | Monaco 日志 | 改动最大、测试重写，放最后 |

每阶段独立可交付、`npm test` 全绿后再进下一阶段；P6 结束时补 `src/data/changelog.ts` 的 0.2.0 条目（按实际改动写"使用者视角"的条目）与 README 相关段落。

## 全局约束

- 不引入除 `monaco-editor` 之外的新依赖（ContextMenu 用现有 reka-ui）。
- 所有新逻辑走既有分层：`api/*` 只做 IPC/HTTP，写操作经 store，视图不直接调写接口。
- 中文注释沿用现有风格：解释"为什么"，不复述代码。
- 测试保持现有覆盖习惯：每个阶段的 store/解析/交互都有用例；jsdom 无布局的地方用伪造尺寸（参考 `LogView.test.ts`）。

## 风险与对策

| 风险 | 对策 |
|---|---|
| Monaco 打包体积与 worker 在 Tauri 中的加载 | 只引 editor.api、独立 chunk、本地资源加载；发版前在真实安装包里手工验证日志标签 |
| Monaco 在隐藏标签中布局为 0 | 可见性变化时 `layout()` + 滚底（对应现有 watcher） |
| 单次部署认领不到 taskId → 不自动上线 | UI 文案写明；通知里区分"未识别到任务"；TTL 兜底 |
| `env` 参数与分页交互（服务端分页链接不带 env） | 分页 URL 由客户端拼装，env 始终带上；测试断言 query |
| 备注/标签被"重新收藏"覆盖 | 元数据用独立命令写入；`*_save` 保留既有 note/tags，Rust 侧加用例 |
| 标签改名/删除留下悬空引用 | 两条级联命令（改名/删除都覆盖单条与批量两份数据）+ Rust 单测；未知标签前端兜底灰色 |
| 单次部署的批次把已有通知行为改掉 | 只在勾选自动上线时才开批次；`single` 批次不进批量页「最近批次」，通知带 taskId 保住点击定位 |
| Monaco 同步算法在进度行/丢行/清空上出错 | 按 id 游标 + 差异行 replace，纯函数 `planModelSync` 全覆盖单测（含 reset 与清空） |
| ContextMenu 与标签点击/拖拽冲突 | Trigger 用 `as="div"`，只在 `contextmenu` 事件上开菜单，不拦截 click |

## 明确不做

- 不做日志搜索的服务端化、不做日志导出格式变更。
- 不做标签分组/层级、不做标签排序拖拽、不做多标签 OR 筛选。
- 不做任务列表的多条件独立输入框（服务端只有一个 `search` 参数）。
- 不做自动上线的"记住上次选择"。
